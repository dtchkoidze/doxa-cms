# 2FA, резервная почта, смена основной

Второй шаг входа на аккаунте (не на продукте): код из приложения-аутентификатора и код на почту. Google Cloud для аутентификатора не нужен — это не «войти через Google».

Логика, таблица, перехват логина, письма, страница кода — **Doxa User**. Хост (Eventer) — карточки в профиле (axios на `/auth/api/...`, как Add email), бренд продукта в QR, запрет для demo.

SQL накатывает разработчик, не migrate:

- `docs/sql/user_two_factor_methods.sql` — таблица способов и колонка `users.backup_email`

## Способы входа (2FA)

У человека может быть почтовый способ, приложение или оба. На одном входе достаточно **одного** верного кода.

**Почта.** Предлагаем включить, только если в аккаунте уже есть `users.email`. Секрета в таблице способов нет: шестизначный код — `users.secret`, как верификация и удаление. Включение не тумблер: сначала код на этот ящик, потом строка способа с `confirmed_at`.

**Приложение.** Можно включить всегда. Генерируем секрет, QR с **брендом продукта** и строка секрета текстом. Человек сканирует (Google Authenticator, Authy, 1Password — один протокол), вводит 6 цифр. Совпало — `confirmed_at`. Пока не подтвердил, на вход этот способ не действует.

**Резервная почта.** Не строка в таблице способов. Это второй ящик (`users.backup_email`). На экране 2FA — явный пункт «код на резервную почту», письмо уходит только после выбора. Верный код = обычный вход, как после приложения. Второй фактор (приложение / основная) после резерва не спрашиваем. Развилки «сбросить 2FA» / «сменить почту» на этом шаге нет.

Пароль при Add email не обязателен. Соцвход без пароля так и остаётся; создать пароль можно на Security, когда почта уже есть.

## Таблица `user_two_factor_methods`

Одна строка на способ. Почта и приложение вместе — две строки. Уникальность: `user_id` + `method` (`email` или `totp`).

| Поле | Смысл |
|------|--------|
| `secret` | только totp, шифровать. Для email — пусто |
| `confirmed_at` | способ действует на вход. Пусто у totp — мастер QR |
| `is_default` | какой способ показать первым. Поставили на один — с остальных этого пользователя сняли |

Вход с 2FA, если есть хотя бы одна строка с заполненным `confirmed_at`. После успешного входа этим способом ставим ему `is_default`, с других снимаем. Первого входа ещё не было, оба только включили — на экране приложение, письмо сами не шлём.

Резерв в эту таблицу не кладём.

## Соцсеть и почта

Соцсеть отдала email, такого ящика в `users` нет — пишем в `users.email` сразу, без нашего кода. Google сказал, что ящик не verified — не пишем, аккаунт без почты. Ящик уже занят — не пишем, страница привязки (пароль или magic link).

Почты не было — позже Add email: код на новый ящик, пароль не спрашиваем.

## Вход

2FA только на **явный** вход: форма, Google, Facebook, mobile. Пока сессия или remember живы (не вышел, сессию не отозвали) — код не спрашиваем. Laravel может восстановить сессию по remember без экрана логина — так и нужно.

Соцвход 2FA не обходит.

Один confirmed-способ — сразу он (если почта — сразу письмо).

Два — экран default. Письмо не шлём, пока default не почта. Переключение явно: «код из приложения» / «код на email». Переключил на почту — тогда письмо. Неподтверждённый totp в выборе нет.

Резерв — отдельный пункт, не третий «сразу».

Пока нет ни одного confirmed — после пароля или соцсети вход как сейчас.

Пароль / Google / Facebook / mobile **не** выдают сессию и не пишут `recordLoginArtifacts`, пока 2FA не пройдена (pending в session, ответ «нужен код»). Код верный — тогда `Auth::login` и журналы.

## Включение и выключение

Demo — как удаление аккаунта: не даём.

Первый подтверждённый способ становится default. Второй включили — default не трогаем, пока человек этим вторым не войдёт.

Снять способ: модалка и **один** код, по первому доступному:

1. Другой включённый 2FA, если есть (снимаешь приложение — код с почты-2FA, и наоборот).
2. Иначе письмо на основную почту, даже если email-2FA не включали.
3. Иначе письмо на резервную.
4. Нечего послать (нет почт, только приложение) — только страшилка: снял без кода, восстановить будет нечем.

Сняли не последний — 2FA остаётся; если сняли default, флаг на оставшийся. Сняли последний — следующего входа без кода. Кнопки «выключить всё разом» нет. Два поля кода сразу не показываем.

Снимаемый totp кодом из того же приложения не подтверждаем, если есть почта.

## Смена основной почты

Без включённой 2FA не даём, алерт «сначала включите 2FA». Это не про **первую** почту: пустой email после соцлогина — по-прежнему Add email, только код на новый ящик.

С 2FA: сначала код 2FA, потом код на **новую**. Два `Otp` на одном экране нельзя; два письма в один `users.secret` нельзя — строго по очереди. Если 2FA — приложение, сначала цифры из него, потом письмо на новую.

Новый адрес ничей: ни `users.email`, ни `users.backup_email` никого, и не своя текущая основная. Код только на новый ящик без 2FA — нельзя.

Старую почту кодом не подтверждаем — её могут не читать.

## Резервная почта

Включение как Add email: код на **этот** ящик. Не совпадает с своей основной. Не занят ни как чужая основная, ни как чужой резерв. Проверка на отправку кода и ещё раз на confirm.

На входе резерв — канал доказательства, не мастер-ключ. После верного кода — обычный вход. Почту и способы чинят уже в Security.

Сделать резерв основной (swap): старая основная становится резервом, резерв — основной. Кнопка в Security, не экран 2FA. Если только что вошёл резервом — второй код на резерв не нужен, модалка. Письмо на мёртвую бывшую основную не слать.

Снять резерв: код на **этот** ящик, затем `backup_email` пустой. Кнопка в Security. Код на основную или 2FA для снятия не спрашиваем.

Смена основной на любой свободный ящик (не резерв): код 2FA, затем код на новый. Если новый — уже подтверждённый резерв, это swap.

## Где код

**Doxa User:** таблица и SQL; сервис способов; перехват login / mobile / Google / Facebook до выдачи сессии; страница `/auth/two-factor` рядом с Login и Verify; API вкл/выкл, challenge, резерв, смена почты; лимит попыток как у логина, отдельный ключ.

**Хост:** вёрстка карточек на `/my-profile/security` и вызовы Doxa API; в actor — включена ли 2FA и список способов без секрета; бренд продукта для QR (`user.two_factor.issuer`); demo-middleware, как на add-email.

Бизнес-проверки не живут в `ProfileController` / `ProfileService` хоста. Вторую таблицу способов на хосте не плодить.

Смена пароля — `POST /auth/api/password` в Doxa, не `api/profile/change_password`.

## Продукты и домены

2FA на **аккаунте** (общая таблица `users`), не на продукте. Один totp-секрет на человека.

Issuer QR, SMTP, from, логотип письма — с **текущего** запроса (канал/хост). Пакет Doxa product не резолвит: хост накладывает `user.two_factor.issuer` и `mail.*` в `ApplyProductContext`. Хост в коде пакета не хардкодить.

Pending challenge — session текущего домена. Вход на одном продукте не закрывает 2FA на другом.

После кода `REG::authSessionContext()` пишет `user_auth_sessions.product` (platform → null). Success URL уже product.

Лимит попыток: ключ включает `request()->getHost()`.
